# 论文引用转换与模板导出

使用已安装的 `paper-citations` 固定工具，不临时重写 PDF 解析或 Excel 映射。目标参数指被引作者/机构，不是筛选论文作者。

图形工作台提供常见联合国系统组织下拉框，按 `模板/<组织代码>/` 加载 `引用采集模板.xlsx`、`名称变体.json`、`字段映射.json`，可选`报告目录.json`。多份变体清单命名为 `名称变体-分组名.json`，由用户选择；其中id必须与组织代码一致。缺文件时停止该组织任务，不回退到UNEP或猜测变体。编号文件按组织分别记住，已有编号不重置。

首页按01论文文件夹、02模板文件夹/组织/变体、03 API Key输入。模型服务设置在高级窗口中，Key仅驻留进程。开始后显示处理进度。

用户希望自行操作时优先打开已安装的“论文引用解析.app”或运行 `paper-citations gui` 打开原生图形窗口，不再把终端配置向导当成图形界面。窗口支持文件选择、目标与编号输入、模板字段映射、两阶段进度、继续已有项目及打开Excel。macOS首次安装可用 `paper-citations install-gui /本地路径/论文引用解析.app` 创建双击入口；应用依赖创建时的Python环境，不能把这个本机启动器当成独立运行时发给别人。

由agent自动执行时，首次创建项目使用 `paper-citations setup PROJECT --run`：真人终端有交互向导；agent使用 `--non-interactive` 并传入已取得的 `--input`、`--template`、`--target`、`--aliases`（有变体时）及 `--id-state`，或明确的 `--paper-current` 和 `--record-current`。已有项目直接 `run --config PROJECT/run.json`。setup自动保存模板副本、映射和运行配置，后续不必重复设置。

标准中文模板与字段名表头可自动匹配；自定义模板遇到未知工作表或列，需要显式mapping或交互选择，不能为省事跳过未知列。agent不能进入等待键盘输入的向导。GROBID仍是单独服务；pip的 `[full]` 安装Docling，项目附有compose.yaml供本地启动GROBID。

运行前从用户或已约定的项目配置取得：输入目录、目标作者/机构、输出目录，以及必需的本地编号状态文件（最后已用的论文号和记录号）；有名称变体时加载本地 aliases JSON；需要 Excel 时加载本地空白模板与字段 mapping JSON。不要猜姓名变体，也不要用其他模板替代指定模板。配置格式见 [本地配置](references/config.md)。

```bash
paper-citations run --input ./input --output ./output --id-state ./numbering.json \
  --target UNEP --aliases ./unep-aliases.json \
  --template ./blank.xlsx --mapping ./template-map.json
```

也可用 `paper-citations run --config ./run.json`。先执行 `paper-citations doctor` 检查依赖与 GROBID。如果当前 shell 找不到命令，读取本skill安装时生成的 `runtime.json`，使用其中的 python 执行 `-m paper_citation_pipeline.cli`；解释器已失效则在当前环境重新 pip 安装，不能伪称已执行。

## 论文语种

固定仅纳入英语论文。工具在解析前用本地语种检测检查正文；非英语论文不调用GROBID、Docling或模型接口，不分配新编号、不进入引用JSON/MD和Excel。缓存重封装同样筛选。英文摘要不能代替正文语种判定；文本不足或混合语言无法判定时先不纳入，并单列“语种待确认”。manifest和excluded目录保留原因及逐页检测结果，进度单列排除数量，不将其报成“未找到目标引用”或处理失败。已分配的历史编号不回收、不重置。

## 证据与收录

- GROBID只接收原始PDF并绕过代理；Docling并行解析正文和表格。JSON是主数据，Markdown仅供阅读，不从MD重建引用。
- 可接受表格串行及样式简化，不能把内容、引用、图表标题、来源注释或前后文丢掉。检查图表上下文关联；无法确定归属时保留原PDF定位和待解决问题，不拼接无关内容。
- 图像本体及其中数据当前不能保证提取；不得把“PDF原件保留”说成“JSON内容全部无遗漏”。
- 无论报告、网页或其他资料，只要引用了目标内容即可进入后续判定。具体报告名称匹配是独立字段；仅提及机构或仅列参考文献不能自动当作有效引用。
- GROBID参考文献漏项时，从Docling的References区恢复目标条目，必须以原PDF对应区域文字验证；保留修复记录与坐标，不改原始TEI。跳过重复页眉，且文末条目本身不算正文引用。
- “为机构编写/委托编写”是来源关系证据，不自动等于机构作者；保留候选及作者角色待判定状态。第三方题名含机构名时，检查 `target_named_in_third_party_source` 中已连接和待连接位置，不能直接算机构署名或忽略可能转引。
- 一位置到一来源一条候选边。同年歧义、多来源范围、原文编号冲突、混合条目保留证据；不会自动预填“已确认”。个人同姓/同名尤其不能凭短别名唯一认定身份。
- 原空白模板始终保留。映射缺列或目标单元格已有内容时先修正本地配置；不得为成功导出删除原模板字段或覆盖已有记录。

## 内部流程检查与接口诊断

用户最新要求智谱参与解析、填表、异常三个环节，不能把“删除独立AI质检入口”理解为删除所有模型调用。界面仍不显示额外检查开关。

首页有Key时，新任务保存不含密钥的api_config，调用固定的内部阶段检查。每10篇一组，每环节一次HTTP请求，每次输入最多24000字符、输出1536 tokens，无自动重试；记录api-stages.json中的真实状态和usage。只发送结构统计和字段映射，不审全文或改写原引用图。没有Key的本地处理不得称为智谱通道已验证。

本地字段、计数、缺失和关联检查照常运行，程序或接口问题统一进入异常日志。旧ai_config不恢复旧版语义审查。复用相同请求结果；失败或同任务输入改变不自动重新付费，需要明确重跑时另建任务。

管理员可显式使用check-api做一次最小连接诊断；日常任务无需额外测试请求。Key仅驻留内存，不写入文件。

## 编号与进度

- 必须加载本地 `id_state`，不能根据文件名、已处理篇数或候选总数猜起始编号。首次建档使用 `init-numbering`，必须明确最后已用的两类编号；只有明确为新项目时才用0。未提供则取得缺失信息后再运行，禁止自动从零开始。
- 同一项目各批次复用状态文件。不要覆盖、回退或清空分配表；失败重跑复用已分配编号。原始证据ID保留，JSON中 `numbering` 映射到Excel展示编号。
- 使用工具内置进度条：转换和逐篇填表同步推进，字段等检查在后台自动执行。报告实际总篇数和失败数，不用引用记录条数代替填表篇数；100%处理进度不等于引用都已确认。模板未配置则不显示填表阶段。

## 运行与交付

运行日志和每篇状态在输出目录。异常汇总为 `exceptions.json/txt`，列明文件、论文、目标、原因及建议；开始前资源错误保存在项目数据/异常日志。未检出目标引用由程序检查候选数为0生成，不能据此断言原文不存在引用或自动排除论文。单篇错误不隐藏，成功包可以先导出；非零退出码必须报告原因。`--expect-target` 只把无目标命中列为问题，不能强造关系。

已有原始解析缓存可用 `--parser-output` 重封装；输出必须另建目录。不同目标使用不同输出目录。已有完整证据包可单独调用 `paper-citations export`，无需重跑引擎。

完成后调用 `paper-citations validate OUTPUT/json`。报告实际处理篇数、结构失败数、候选条数与原文歧义；说明候选不等于已确认引用。保留XLSX旁的provenance JSON，用于回查模板、映射及源包哈希。

本skill调用的工具版本为0.8.x；依赖GROBID服务与Docling模型。代码更新和公开发布分开；用户要求开发不等于授权上传论文或发布仓库。

参考文献分区对账固定在转换代码中执行。JSON的reference_region_audit记录Docling已识别参考文献区中目标条目的去向：present/recovered/unresolved；未通过原PDF核验的条目进入unresolved和异常日志，不能静默跳过。此检查范围有限，不等于全部参考文献召回率认证。GROBID的funding等区域误分类可能导致漏项，专用参考文献接口仍可能重复同一分区错误；不要盲目重试或把article/light-ref直接设为默认。

0.7.6：识别机构全名[缩写]的作者年份标记；原PDF对账允许横线字形差异但不改原文或数字。带原PDF明确编号的完整Docling条目，可在各片段文字完全覆盖且坐标一致时合并GROBID误拆条目，并同步引用边。报告覆盖年份与出版年份分开保留。PDF定位前缀为数学集合符号∈/∉的区间不计文献引用；[15–17]等真正引用仍按既有规则处理。零候选日志区分目标参考文献未识别与正文索引未连接。


0.7.6内部校验：内置UNEP/EEAP及U.N. Environment变体；用户旧本地变体文件不会被默默覆盖。独立PDF作者年份标记对账，即使已有引用也检查重复次数缺口；未知“已知简称/附属署名”进入日志，不自动承认新身份。此项不覆盖所有数字引用或无标记转述。
上下文在保留原始索引和偏移的前提下，以PDF缩进、连续行距及共享Docling文本块重建；context_audit保留原值与证据。无证据时不重分段；该校验不等于语义或全篇段落边界认证。
AI填表环节在Excel保存和本地回读后执行，输入包含实际文件哈希、逐格比对总数、错误单元格签名及位置，而不是仅有预计行数。api-input-*.json留存模型真实输入，未向模型发送全文。请求仍为每10篇每环节一次，失败不自动重试。自动校验与模型通道成功不得表述为全篇无漏引。

模型返回须通过确定性证据约束：仅采纳输入证据中已存在的论文和异常代码；原始返回与未采纳项分别保留在raw_result、unsupported_findings。参考文献条目数不要求等于正文引用次数。模型仅解释结构检查结果，不独立认证召回率；本地异常不因模型漏报而被清除。


0.7.7运行约定：转换程序自动读取原PDF文字及坐标作证据核验，日常批次不要求agent逐篇人工回看PDF。JSON保留原始索引、引用上下文、修复依据和未解决项；异常未解决不能表述为全篇无漏引。用户明确要求审计或问题无法定位时，才按需检查原文。
最后一次逐篇快照的输入JSON、模板、映射、编号文件及输出附件哈希全部一致且检查点完成时，复用该快照；仍执行最终回读检查。任一项变化或不完整则重新导出。
每篇完成MD/JSON后立即保存累计Excel快照并回读检查，进度分母为任务总篇数；无需等待整批API检查。中断前已保存的结果可用，编号保持稳定；运行中的表格是部分结果，不代表全批完成。检查点记录在citations.checkpoints.json。为保持模板、报告去重和编号一致，每次从已完成JSON生成累计快照，保存成本随批量增长；并非Excel应用内实时刷新。
批内复用独立Docling进程和模型，GROBID与Docling仍并行；单篇超时/崩溃结束该worker，后续论文重新创建。首篇仍需模型冷启动。不以跳过表格结构、引用检查或无依据截短上下文换取速度。内部AI仍仅作结构检查，不宣称已使用多模态模型审读PDF。


0.7.8新增引用恢复：个人作者署名的目标出版物使用本地完整姓氏与年份、在全部参考文献中唯一匹配，保留推断依据；同名同年不强行连接。数字引用漏进正文索引时，从原PDF标记与参考文献实际印刷编号补回，禁止用列表顺序猜编号。表格文号保留原始代码，不虚构题名/年份；破碎的资源表按PDF列标题、年份行锚点和内嵌官方来源链接恢复整行。仅列管理机构的行留在recall_audit待分类，不当作引用。
目标机构单独或共同署名都纳入，保留完整署名。复合署名需结合参考文献作者位置，不能只凭连字符认定，也不要求为每个共同作者组合加组织同义词白名单。疑似作者角色由后台API根据完整参考文献与解析作者字段判定，保留角色、原文证据及理由；不确定或失败记录异常，不丢弃候选。每篇最多5次、每次512输出token、无自动重试，输入及结果缓存防止重复收费。已存在目标参考文献而无正文连接也产生检查提示，不能只依赖零命中警告。
上下文修复须核验Docling段落与原PDF行位置，防止跨页截断，也不能用局部Docling片段替换更完整的原上下文。原TEI、解析缓存及原始引用偏移始终保留。


0.8.0：采用通用共同署名规则，不设UNEP-WCMC专属白名单。Excel“匹配到的具体报告名称”只有匹配确定时填名称，其余填数值0；不使用未核验的解析题名冒充匹配结果。引用本身仍收录，匹配状态与原始文献保留，0不代表没有引用。


0.8.1：参考文献标题允许■等装饰符；恢复PDF核验通过、带实际(6)/[6]编号的年尾式条目，并把已有上标数字连接到原文编号，禁止按书目顺序猜号。共同作者识别支持作者列表后接题名、年份在条目末尾；未能确认的复合署名继续进入作者身份API候选。
明确数据来源使用单列为citation_form=explicit_source_use_without_marker：在原PDF同一句中同时找到目标来源、数据资源和实际使用表述，保留原段落、坐标及该句网址；raw_marker为空，不编造文末参考文献。排除未使用、仅介绍来源、作者单位及已连接正式引用的重复记录。其报告名称未核实填0。这是保守规则，仍不保证所有隐含转述均被找全。
API结构摘要同时携带参考文献分区未核验项及不可用状态，不能把分区不可用当作校验通过。

0.8.2：从本篇参考文献作者位置建立“机构全称（简称）”及共同署名关系，规范简称内换行/连字符空格，不把本篇关系写成全局别名。对有本地目标书目支持、同句明确使用的数据库名称，可单列无标记来源使用；不据名称猜测版本/年份，存在不同作者的同名资源时不自动归属。无标记政策借用进入待判定问题，不创建已确认引用边。首页元数据修复保留PDF证据，原始解析数据不改写；标题网页按钮标签、摘要和出版页脚年份仅在条件满足时补正。仍须报告区域核验失败、元数据缺失和上下文分类局限，不能用运行成功代表无遗漏。

0.8.3：排除明确的公式/图表/章节交叉指引；从原PDF还原上标列表与跨行范围，保存完整原标记。带点的文末编号同样从原文读取，不按书目顺序补号。Docling可用于合并同一位置的残缺作者/题名片段、拆出混入相邻条目的目标书目；完整PDF文字覆盖及坐标核验必需，不能因段落包含目标词就创建第二份重复来源。本篇冒号署名、全称与缩写共同署名及专家组署名需由作者位置支持；多网址逐一检查域名。缺少标记坐标时仅在原段落区域内唯一找到原标记后补定位。斜向水印不参加水平书目分行。原PDF文字层可校正Docling损坏的书目文字，但须有确定的条目边界、原文编号和作者证据。无标记政策描述、仅题名含机构而作者角色不明的来源单独列异常待判定，不制造已确认边。首面未连接上标仍保守处理，不能把作者单位编号或单位指数当引用。

0.8.4：引用范围也支持原PDF中的[a]–[b]及跨行形式；只有原文坐标与已有引文锚点一致才补全。双栏文末声明打断参考文献读取顺序时，须由GROBID书目位置和原PDF文字共同验证继续恢复。拆开的条目只保留本条原文支持的作者、DOI及出版信息。引号内题名中的机构名不能当共同作者；明确出版方字段单列出版证据，不冒充作者署名。脚注引用需同时核验正文上标与本页脚注编号；supra回指冲突时保留引用、报告匹配填0并记录冲突，不改原文编号或猜报告。当前不保证跨页脚注、ibid/同上、图像内文字和所有隐含转述召回。回归比较应覆盖来源与定位，不能只比较条数。


0.8.5：脚注编号支持与正文同字号及独立PDF行对象；必须核验正文上标和同页脚注。支持唯一的 above n 回指；At/ibid 简写仅在同页紧邻前条且来源单一时连接，跨页或混合来源不猜测。脚注正文上下文排除注释及页眉；跨页连接需原PDF末段未完句、次页首段小写连续及字号一致，句子边界标为PDF规则提取而非GROBID。支持完整机构共同署名后接题名；带点编号粘入Docling条目时经坐标核验去号对账。机构名误当题名只能在原PDF区域完整核验后修复。重复卷期页眉可补出版年，提交学位年份不作出版年。名单中的论文可能只引用UNDP等其他机构，零UNEP命中不得强行收录。


0.8.6：单篇后处理使用有界原PDF证据会话，各模块共用文档句柄和完整页文字提取；区域裁剪仍由原生引擎执行，调用者获得独立副本，缓存不跨论文保留。报告目录每批预编译，同篇相同题名/原条目/年份匹配复用；不改变引用规则、来源或不确定状态。JSON provenance记录读取缓存统计。性能报告须区分后处理与GROBID/Docling/Excel全流程；不得把缓存提速当作召回率提高。
